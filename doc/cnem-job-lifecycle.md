# 检验结论作业生命周期 · 册下口径

对应问答需求与实现：`com.fc.v2.service.impl.TCnemJobServiceImpl`，
表结构见 `doc/schema/cnem.sql`。界面本轮不碰。

## 一、作业号与行（报）

- 一批设备先有**作业号**，作业号是系统在册上排出来的，报送人手里没有填号的格子。
- 同作业号在册只占一个**作业头**（`t_cnem_job.row_no=0`）+ N 个**作业行**
  （`t_cnem_job_row.row_no=1..N`）；有几台就是几行，行次系统从上往下排，报上去不许自己挪。
- 同号再递一回**不另立新行**：头在就原样返回，已报的行一个字不动。
  数据库 `uk_job_head(job_no,row_no)`、`uk_job_row(job_no,row_no)` 兜底；并发两笔同号报送，
  先到的占住，后到的按"不另立"处理。
- 报上头状态为**待审(1)**，报了先候着。

## 二、三段状态机（报 → 做 → 收）

```
1待审 ──effect──▶ 2生效中 ──▶ 3已生效（全部做成）
                     │           └▶ 4部分生效（有台没做成，或一台没做成）
                     └────────────▶ 4部分生效
3/4 ──rollback──▶ 5回滚中 ──▶ 6已回滚
```

- 只有 **1待审** 能进"做"；只有 **3已生效/4部分生效** 能进"收"。不能跳段，不能倒着走。
- 状态推进全部走 **CAS**：`update ... set status=新 where id=? and status=旧`，
  影响行数为 0 即"没轮到/已被先到的一笔定了"，本次调用什么都不改，返回 0（它不理）。
  同刻压上的两笔，后到的不得把先到已定的结果覆掉。
- 已经做完的、已经收回的再喊"做"，不理；收到一半（头在 5回滚中）也不许再往前做。

## 三、做一台：先看判据，再四处同刻落定

做之前每台都指着一条检验判据（`t_cnem_job_row.rule_id`）：

| 判据情形 | 处置 |
|---|---|
| 册上压根没有（行没指 / 指的 id 不存在 / 已删除） | 这台**没做成**，写明原因 |
| 判据撤了（`status=1`） | 没做成，原因"已撤下，不认" |
| 判据过期（当前时刻 ≥ `eff_end`，截止时刻不含） | 没做成，原因"已过期" |
| 判据未生效（当前时刻 < `eff_start`） | 没做成，原因"尚未生效" |
| 启用且在生效时段内 | 按 `th1/th2/th3` 分 1/2/3/4 档 |

几份判据同时适用时以哪份为准，照判据册的优先级口径（`priority` 大者优先）取，本行只认自己指着的一条。

做成的一台，**四处同一时刻落定**（每台一个独立事务，行级 `for update`）：

1. 检验结论册子上的行：`t_cnem_job_row` → 做完(3)、写回标记=1；
2. 台账：`t_cnem_insp_ledger` 落一条（在档 status=0，含结论等级、判据、版本、金额）；
3. 收费流水：`t_cnem_fee_flow` 落正账一笔（flow_type=1）；
4. 留痕：`t_cnem_job_oplog` 落一笔（谁、什么时候、哪台、从什么状态到什么状态）。

**少落一处，这一台就不算做完**：任何一处异常整台事务回回，记一笔异常留痕，不拖垮别台。

**别把整批推翻**：哪台没做成，只把那台留在册上（行=4，`fail_reason` 写明判据这边出了什么状况），
其余几台照做。头状态：全做成=3已生效，只要有没做成的=4部分生效。

## 四、收回：补冲账流水，不删结论

- 收回做过的结论**不是删台账行**，而是一处一处冲回来（每台独立事务）：
  - 台账行保留，`status` 0在档 → 1已冲账；
  - 补一笔**冲账流水**（flow_type=2，金额为正账的负值），`uk_fee_flow_row(job_no,row_no,flow_type)`
    保证同一台冲账流水**该写几道写几道，不许写第二道**；
  - 作业行 → 已收回(6)，补偿标记置位；
  - 留痕一笔。
- 只收做成过的（行=3）；没做成的（行=4）、没做过的、已经收回的，不动。
- 整个收回操作再调一次是幂等的：不写第二道冲账流水，返回 0。

## 五、老数据口径

存量老行照口径接着走，**系统不因缺项把老行整批回退**：

- 判据版本没写：不拦，做成时以判据编号回填；
- 检验编号空着：台账/流水该列就空着，不编；
- 运行小时空着：结论等级那一格空着（`grade_level=null`），不影响四处落定；
- 但"行压根没指判据 / 指的判据在册上查不到"属于**判据缺失**，按第三节判这台没做成并写明原因
  （判据是"做"的前提，缺前提不是缺展示项）。

## 六、回头怎么查

`traceJob(jobNo)` 一张轨迹给出：

- 作业头当前在哪一段、总行数/做成/没做成计数；
- 每一行状态与失败原因；
- **落定几台 / 没落成几台 / 收回几台**；
- `halfRows`：行说做完或收回了，但台账或流水缺一笔（只落一半/收到一半）；
- `duplicateReverseRows`：同一台冲账流水出现一道以上（正常被唯一键挡死，脏数据可倒查）；
- 留痕按操作时刻**倒序**（同刻后到的在前），谁动的、什么时候动的都在。

## 七、并发与事务落点

- 作业头推进：CAS update，无锁、先到先得；
- 单台落账：`REQUIRES_NEW` 独立事务 + 行级 `select ... for update`，台与台互不拖垮；
- 四处落定同生共死：库异常 → 整台回回 + 独立事务补异常留痕；
- 幂等：报送（唯一键）、做（CAS 头 + 行状态）、收（CAS 头 + 行状态 + 冲账唯一键）。
